# ck-run v4: user guide (2026-11-05)

This guide covers every command and flag that v4 adds to `ck-run`. Old commands, guards and rules still work as the
README says, except where this guide says they changed. If this guide and `ck-run <command> --help` disagree, tell
chalach: one of them is wrong.

In the examples: `PHD={{PHD_ROOT}}` and
`ck-run` = `~/PhD_local/ck-dispatch/bin/ck-run`.

## 1. The new ideas

| Idea | What it means |
|---|---|
| **Ask** | One request from chalach. Every run, review and fix carries its `ask_id`. chalach sees one start card and one finish card per ask, not one report per run. |
| **Size** | S, M or L. Each size has a budget (runs, reviews, fixes, minutes) that ck-run counts. Over budget: exit 7, nothing starts. |
| **Pattern** | How agents work together: `solo`, `pair`, `race`, `split`, `panel`, `loop`. |
| **Review reason** (`--trigger`) | A review needs one: `leaves-lab`, `hardware-or-raw`, `agent-unsure`, `you-asked`. No reason, no review. |
| **Tier** | `fast`, `strong`, `top`. The ask size picks the tier; the tier picks the model. |
| **Launch** | `ck-run launch` writes the launch file and starts the run detached. The run survives a Claude restart. |
| **Watchdog** | A stuck live run is caught after a few minutes, not at its timeout. The Mac stays awake while a run waits. |
| **Views** | `board`, `digest`, `recall`, `scoreboard`, `rules`: read-only, made from the ledger and the config. |

## 2. A whole ask, start to finish (example)

```
cd "$PHD/Device Fabrication"
ck-run ask open --words "<task request>" --size M \
  --title "Save the SPCM kit and write one wiki page" --project fnd_sin
#   prints the ask id on line 1 (for example A-EXAMPLE-4), then the start card

# write the task file: ~/PhD_local/agent_runs/A-EXAMPLE-4-wiki_prompt.md  (chalach's words + "Do only this: ...")
ck-run launch A-EXAMPLE-4-wiki run --ask A-EXAMPLE-4 --model sol --workspace devfab --title "SPCM kit wiki page"
#   prints 4 lines: slug, sh, out, pid. Returns at once; the run opens in iTerm2.

# when ~/PhD_local/agent_runs/A-EXAMPLE-4-wiki.out ends with "ck-run exit=N":
ck-run ask close A-EXAMPLE-4 --done yes
#   prints the finish card and accepts the ask's open runs
```

Slugs: ckstack's convention is `<ask id>-<word>` (for example `A-EXAMPLE-4-wiki`, `A-EXAMPLE-4-fix1`,
`A-EXAMPLE-4-review-claude`). A slug is used once.

## 3. Exit codes

| exit | status | meaning |
|---|---|---|
| 0 | ok | as before |
| 1 | partial | as before |
| 2 | refused | a guard said no, or a usage error. New cases: unknown or closed ask, `--ask` missing (when required), review without `--trigger` (or a run with it), a model alias for another agent, andon raised, launch slug used |
| 3 | failed / timeout / stalled | as before, plus a run stopped by the watchdog (note: `stopped by the watchdog: no activity for N s`) |
| 4 | flagged | as before |
| 5 | violation | as before |
| 6 | busy | as before (claim conflict) |
| **7** | **over budget** | **new.** The ask's budget is used up. Nothing started. stderr: `ck-run: OVER BUDGET: <message>` |

## 4. Asks

### 4.1 Open an ask

```
ck-run ask open --words "<chalach verbatim>" --size S|M|L --title T [--project P]
                [--pattern solo|pair|race|split|panel|loop] [--models a,b,c]
                [--parallel N --because "<chalach words>"] [--plan FILE]
```

| Flag | Meaning |
|---|---|
| `--words` | chalach's words, copied exactly (required). |
| `--size` | `S`, `M` or `L` (required). Grok Bot picks it; chalach's size words win ("quick", "short", "for now", "no review" mean S). |
| `--title` | The goal in Grok Bot's own words (required). It is the goal line of the start card, so chalach can catch a wrong reading before any agent starts. |
| `--project` | Short project name, for example `fnd_sin`. Views group by it, and the andon uses it. |
| `--pattern` | `solo` (default), `pair`, `race`, `split`, `panel` or `loop`. |
| `--models` | Model aliases, comma-separated, for example `astra,opus,grok`. |
| `--parallel N --because "<words>"` | More runs at the same time, only with chalach's words. Sets parallel = N and runs = at least N. |
| `--plan FILE` | L only. A plan file. A line like `budget: runs=8 parallel=3` in it sets runs, parallel, reviews, fixes and wall_min. |

Output: line 1 is the ask id. Then the **start card**, at most 4 lines: the id, the title, size, pattern, the models
(if given) and the budget. Exit 0.

The ask id is `A-MMDD-N` (month, day, and N = 1 + the asks already opened that day), for example `A-EXAMPLE-4`. It is
made under a lock (`<runs_dir>/.asks.lock`), so two asks never get the same id. There is no second database: the
state of every ask comes from the ledger.

### 4.2 Budgets

| | S | M | L |
|---|---|---|---|
| runs (fixes count here too) | 1 | 2 (1 + 1 fix) | 6 |
| parallel (live at the same time) | 1 | 1 | 3 |
| reviews | 0 (1 with trigger `you-asked`) | 1 | 2 |
| fixes (runs with `--parent` in the same ask) | 0 | 1 | 2 |
| wall_min (minutes since the ask opened) | 15 | 45 | 180 |
| timeout per run, when `--timeout` is not given | 600 s | 1800 s | 7200 s |
| stall_s (watchdog) | 180 s | 300 s | 480 s |

- The numbers live in the config block `asks` in `config/workspaces.json`. The code has the same defaults.
- **race** (any size): runs = the larger of the budget runs and the number of race models (default 3, from
  `race_default`); parallel = the number of race models. Those runs may use the top tier.
- `--parallel N --because "<chalach's words>"` at open: parallel = N, and runs = at least N.
- `--plan FILE` (L only) may set runs, parallel, reviews, fixes and wall_min.
- A run without an ask keeps the old timeout default (`default_timeout_s`, 1200 s) and a watchdog stall time of 300 s.

### 4.3 The budget gate (before every run and review)

- `asks.required` is true in the real config. Then a run or review without `--ask` is refused (exit 2), and the
  message shows the exact `ck-run ask open ...` line to use. (In the test sandbox it is false by default.)
- Unknown ask: exit 2. Closed ask: exit 2 ("closed; open a new ask"). Parked ask: over budget.
- **Over budget (exit 7)** when: runs used ≥ runs; fixes used ≥ fixes (for a `--parent` run; not counted in an ask
  opened with `--pattern loop`); live runs (reviews too) ≥ parallel; reviews used ≥ reviews; the wall time is over;
  or `--tier top` in an S or M ask that is not a race. Over wall time also parks the ask (`ask_park`, reason
  `over time`).
- The message names the use and the limit, and ends with the way out, for example:
  ```
  ck-run: OVER BUDGET: ask A-EXAMPLE-4 (M) used 2/2 runs. To go over, add --over "<chalach's words>"
  ```
- Each refusal is a ledger event `over_budget` (status `refused`).

**`--over "<chalach's words>"`** (run and review; not empty): lets this ONE dispatch pass the budget checks. The
ledger gets `over_budget` with status `approved` and `over` = the words. It never passes the guards, the claims, the
andon or any safety rule. Use it only with words chalach really said.

### 4.4 Close, park, later, answered, list, show

```
ck-run ask close <ask> [--done yes|partial|no] [--note TEXT]
ck-run ask park <ask> --reason TEXT
ck-run ask later <ask> ["<item>"]
ck-run ask answered <ask> --summary "<1-3 lines>"
ck-run ask list [--open] [--since 7d]
ck-run ask show <ask>
```

| Command | What it does |
|---|---|
| `ask close` | Prints the finish card. Ledger `ask_close` (status `done`, `partial` or `not_done`, the card, the note). Without `--done`, the status comes from the runs' results. Runs with no accept or reject yet: ok and partial runs get accepted (rejected with `--done no`), failed or timed-out runs get rejected, and flagged or violation runs are left for chalach (`ck-run accept`). Safe to run again: a closed ask prints its card. |
| `ask park` | Parks the ask: no new run or review passes the gate (over budget) unless chalach's words come with `--over`. Ledger `ask_park`. |
| `ask later` | With an item: adds it to the ask's Later list (ledger `later_add`). Without: lists the items. The Later list = the agents' `later` ideas plus the items added here. They are ideas NOT done; nobody works on them until chalach says so ("yes 2" = start item 2 as a new ask). |
| `ask answered` | Grok Bot answered an S ask itself, with no agent. Ledger `answered` (the note = the 1-3 line summary); then it closes the ask (DONE) and prints the finish card. |
| `ask list` | Lists asks with their budget use. `--open`: only open and parked ones. `--since 7d` (or `12h`): only recent ones. `--json` too. |
| `ask show` | One ask: its card, budget use, runs, Later list, and the finish card once closed. `--json` too. |

### 4.5 The cards

The **start card** (`ask open`, at most 4 lines): id, title (the goal in Grok Bot's words), size, pattern, models
if given, budget.

The **finish card** (`ask close`, plain words, at most 8 lines, no run ids):

```
<ask>  <sample task>   DONE   <runs>, <time>
Changed: <plain_summary lines of the runs, merged, at most 3 lines>
How sure: <lowest verification level of the runs>
You should know: <you_should_know, at most 2 lines>
Your move: <your_move lines, or "nothing">
Later (N): <later items, numbered, short>
```

The status word is `DONE`, `PARTIAL` or `NOT DONE`. "How sure" shows the LOWEST level of the ask's runs (an ask
that Grok Bot answered itself: desk check):

| `verification` in result.json | Card says |
|---|---|
| `hardware` | hardware test |
| `local_sim` | local sim you ran |
| `fake_or_tests` | fake data or tests |
| `desk_check` | desk check |
| `not_checked` | not checked |

## 5. run and review: new flags

```
ck-run run    [--agent A] --workspace W --title T --prompt-file F ... [--ask ASK] [--over "<chalach's words>"]
              [--model ALIAS|ID] [--tier fast|strong|top]
ck-run review RUN_ID [--by AGENT] --trigger leaves-lab|hardware-or-raw|agent-unsure|you-asked
              [--ask ASK] [--over "<chalach's words>"] [--model ALIAS|ID] [--tier fast|strong|top]
              [--focus TEXT] [--blind] ...
```

(`--agent` on run and `--by` on review may be left out when `--model` is an alias.)

- `--ask ASK`: the ask this run belongs to (required when `asks.required` is true). Every ledger event of the run
  carries the ask id.
- `--over "<words>"`: see 4.3.
- `--model`: a model alias (section 6) or a raw model id. An alias implies the agent, so `--agent` may be left out
  (`--model sol` = codex). An alias for a different agent than `--agent` (or `--by`) is refused (exit 2).
- `--tier fast|strong|top`: see section 6.
- `--timeout`: when not given, the default comes from the ask size (S 600 s, M 1800 s, L 7200 s).
- `review` needs **`--trigger`**, one of the 4 reasons below. Missing: exit 2. S asks accept only `you-asked`.
  A review without `--ask` belongs to the ask of the reviewed run. `--trigger` is for reviews only: a run with it is
  refused (exit 2).

| Review reason | When |
|---|---|
| `leaves-lab` | numbers or claims go into slides, a paper, a patent, VC or AQS material, an email, or a purchase |
| `hardware-or-raw` | code that drives lab hardware, or touches raw data |
| `agent-unsure` | the result is partial or "not checked", or a `guess` on a choice that matters |
| `you-asked` | chalach asked for a review ("check it", "review", "deep") |

## 6. Models and tiers

`config/models.json` is the source of truth. `ck-run models` prints it as a plain table: the aliases (agent, model,
effort, tier), the tier table, `size_tier`, `race_default` and the lanes (`--json`: the file itself).

| Alias | Agent | Model | Effort | Tier |
|---|---|---|---|---|
| `sol` | codex | gpt-6.1-sol | high | strong |
| `sol-fast` | codex | gpt-6.1-sol | low | fast |
| `astra` | codex | gpt-6-astra | (none) | top |
| `opus` | claude | opus | high | strong |
| `opus-max` | claude | opus | xhigh | top |
| `sonnet` | claude | sonnet | medium | fast |
| `haiku` | claude | haiku | (none) | fast |
| `grok` | cursor | grok-4.7-high (Grok 4.7 at high effort; Cursor's slug) | (none) | strong |
| `composer` | cursor | composer-2.5 | (none) | fast |
| `gemini` | agy | (agy's default) | (none) | fast |

| Agent | fast | strong | top |
|---|---|---|---|
| claude | sonnet | opus | opus-max |
| codex | sol-fast | sol | astra |
| cursor | composer | grok | grok |
| agy | gemini | gemini | gemini |

- `size_tier`: S = fast, M = strong, L = strong. Without an ask: strong.
- The run's model is `tiers[agent][tier]` unless `--model` is given.
- The top tier is used only for an L ask with `--tier top`, and for race runs. A top model that chalach names
  (for example `--model astra`) is always allowed. `--tier top` in an S or M ask (not a race) is over budget (exit 7).
- `--tier` next to an alias is not used: the alias has its own tier (a note says so). A raw model id needs `--agent`.
- `race_default`: `astra`, `opus`, `grok`.
- The ledger records the resolved model id in `model`, plus `model_alias` and `tier`.

**Effort.** ck-run adds the model and effort flags to the agent's command itself. You can never pass them (the
guards refuse `--effort`, `-m`, `-c` and the like from you, as before).

| Agent | What ck-run adds |
|---|---|
| claude | `--model opus\|sonnet\|haiku`, and `--effort <level>` when the alias has an effort |
| codex | `-m <model>`, and `-c model_reasoning_effort="<effort>"` when the alias has an effort (astra: none) |
| cursor | `--model <slug>` |
| agy | no model flag (its CLI only lists models with `agy models`); Gemini is agy's default |

`_verified` in `config/models.json` records what was checked on this Mac (from the CLIs' help text, read-only). An
effort value that could not be checked is marked `TODO(verify)` there, and ck-run then passes no effort flag.

**Lanes** (who does what by default; chalach can always name another model):

| Lane | Worker | Also good | Check |
|---|---|---|---|
| `quick` | Grok Bot itself | sonnet, composer | none |
| `lab-code` | sol | astra, grok | opus |
| `bug-fix` | sol | astra | opus |
| `numbers` | sol | opus, grok | opus |
| `wiki` | sol | composer, gemini | sonnet |
| `writing` | opus | astra, grok | sol |
| `decision` | race | | none |
| `loop` | sol-fast | composer, sonnet | astra |
| `repo` | sol | astra | opus |
| `scout` | grok | sol | opus |
| `mechanical` | composer | gemini | none |

`ck-run route --lane <name>` prints the worker, also and check of a lane as agent + model, and skips agents that
are rate-limited (the same limits logic as before). `ck-run route --task-type T` still works as before.

## 7. Launch: start a run detached

```
ck-run launch <slug> run|review|loop [args...]
```

Prints 4 lines: `slug: ...`, `sh: ...`, `out: ...`, `pid: ...`, and returns at once.

- `<slug>`: a letter or digit first, then letters, digits, `_`, `.` or `-` (at most 64 characters).
  Files: `~/PhD_local/agent_runs/<slug>.sh` and `~/PhD_local/agent_runs/<slug>.out`.
- `args` are the normal ck-run arguments after `run`, `review` or `loop`.
- A `run` needs `--prompt-file` with a file inside `~/PhD_local/agent_runs/`. If you leave it out and
  `~/PhD_local/agent_runs/<slug>_prompt.md` exists, launch adds it for you.
- launch adds `--interactive` to `run` and `review` unless `--no-live`, `--live` or `--interactive` is there already.
- A used slug is refused (exit 2, "slug used; pick a new one"): a slug whose run is still going (no `ck-run exit=`
  line in its `.out` yet), or one used before. Pick a new slug every time.
- The `.sh` has a comment header (title, ask id, chalach's words from the ask, the time) and one command line:
  `cd <folder> && <ck-run> <args> "$@"`. The folder is where you ran `ck-run launch`.
- The run starts in its own session (`/bin/bash`, stdin `/dev/null`), so it survives the Claude or Grok Bot session
  that started it. Its output goes to `<slug>.out`; the last line is `ck-run exit=N`. Ledger event `launch`.
- With `--dry-run` (or `--help`) in the args, launch writes and starts nothing: it shows the `.sh` it would write and
  runs the ck-run dry run in the foreground. Use it to check a launch first.

Examples:

```
ck-run launch A-EXAMPLE-4-wiki run --ask A-EXAMPLE-4 --model sol --workspace devfab --title "SPCM kit wiki page"
ck-run launch A-EXAMPLE-4-review-claude review <run_id> --by claude --trigger hardware-or-raw --ask A-EXAMPLE-4
ck-run launch A-EXAMPLE-7-loop loop --ask A-EXAMPLE-7 --model sol-fast --prompt-file ~/PhD_local/agent_runs/A-EXAMPLE-7-loop_prompt.md \
  --workspace devfab --metric "python3 metric.py" --target ">=<number>" --max <N>
```

(The values in angle brackets are yours to fill. A loop needs an L ask with enough budget: see section 14.)

## 8. Live windows: tabs, watchdog, keep awake

- **One window per ask.** With iTerm2, the runs of one ask open as tabs in one window (state in
  `<runs_dir>/.windows/<ask id>.json`). If that window is gone, a new one opens. A run without an ask opens its own
  window, as before.
- **Close the tab.** A run that finished cleanly closes its tab after `live.close_tab_after_s` (default 600 s; 0 =
  never). This never holds up ck-run's exit.
- **Keep the Mac awake.** While a live run waits, ck-run runs `/usr/bin/caffeinate -i -w <ck-run pid>` (config
  `live.keep_awake`, default true; skipped if the program is missing). It stops idle sleep, not sleep when the lid
  closes on battery.
- **Stall watchdog.** Activity = the window's last lines changed (iTerm2), or a file in the run folder or the agent's
  session store grew. With no activity for `stall_s` (S 180 s, M 300 s, L 480 s; 300 s without an ask), ck-run reads
  the window's last lines:

| It sees | It does |
|---|---|
| sleep ("went to sleep") | types `continue` + Return into the run's own tab ONCE; ledger `resume_sent` (if that cannot be done, or the agent stays quiet: `stall` + notification) |
| an approval prompt ("Do you want", "Allow", "[y/n]", "approve") | ledger `stall` + one Mac notification |
| a rate limit | marks the agent limited (`ck-run limits`), ledger `stall`, notification |
| anything else | ledger `stall` + notification |

  With no activity for 2 × `stall_s`, ck-run stops the run (ledger `watchdog_stop`). The run ends as `timeout`, exit
  3, note `stopped by the watchdog: no activity for N s`. Each reason gives at most one `stall` event and one
  notification per run. Time the Mac slept does not count as silence.

## 9. Reattach: finish runs whose watcher died

```
ck-run reattach [RUN] [--since 24h]
```

- Without RUN: for each run that started (a `dispatch` or `review` event) and has no `result`, and whose ck-run is
  gone: if its agent still runs, ck-run starts a detached waiter (slug `reattach-<end of the run id>`) that finishes
  the run when the agent ends; else it finishes the run now. Ledger `reattach`. `--since` (default 24h; e.g. `6h`,
  `2d`) limits this to runs started in that time.
- With RUN: only that run.
- "Finish" = build the result from what is on disk (packet.json, result.md or result.json, summary.md, the agent's
  session), run the normal rule check, write the `result` event (note: `finalized by ck-run reattach: <note>`) and
  print the summary path and summary like a normal run. The exit code is the run's.
- Safe to run again: a run that already has a result just prints it. A run whose agent is still running is refused
  ("agent still running").

## 10. Views (read-only)

```
ck-run board [--json] [--md [PATH]]
ck-run digest [--since 1d|7d]
ck-run recall <project>
ck-run scoreboard [--since 30d]
```

| Command | What you get |
|---|---|
| `board` | **NEEDS YOU**: parked asks, over-budget refusals with no approved dispatch after them, flagged or violation results not accepted, `stall` events of live runs, open-question lines from results of open asks. **RUNNING**: one line per live run (agent + model alias, ask id, title, minutes, the window's last line when known, else the newest file in its run folder). **DONE TODAY**: asks closed today (id, title, status, how sure, your move). `--json`: a dict with `needs_you`, `running`, `done_today`. `--md`: writes markdown to PATH (default `~/PhD_local/BOARD.md`). |
| `digest` | Per project (the ask's project, else the workspace): asks done, runs, agent minutes per model alias, the lowest verification level, open items. Plain text. Good for a PI meeting. |
| `recall` | At most 5 short lines on the project, then one line per ask with one tag (`running`, `done`, `parked`, `needs you`, `later`), then the next move. |
| `scoreboard` | Per lane, model alias and agent: runs, ok rate, accept rate, median minutes, fix rounds. |

`digest` takes `--since 1d` by default; `scoreboard` `--since 30d`. `digest`, `recall` and `scoreboard` also take
`--json`. `recall` takes an ask project (for example `fnd_sin`) or a workspace key.

## 11. Rules: what each agent may do

```
ck-run rules [--check]
```

- `ck-run rules` prints a plain table per agent (where it may edit, web, git push, pip install, cloud sims, post-run
  review, default models), built from the real code and config, then any DRIFT lines, then chalach's decisions from
  `config/policy.json` (each with its date and chalach's words; `UNKNOWN` where no words were recorded).
- `--check` prints one `DRIFT` line for each place where the config or code disagrees with a decision, and exits 1
  when there is drift (0 when there is none). It checks at least: git push and pip install (allowed 2026-11-04) vs
  the denies in `config/claude-guard.base.json`; web (allowed 2026-11-05) vs denies; post-run review off vs
  `post_review.enabled`. It only reports. The build does not change `claude-guard.base.json`: that is chalach's open
  question. On the v4 build (2026-11-05) it printed 4 DRIFT lines: the guard's git push and pip install denies, and
  the two agent-prompt hard rules that still say no git push and no pip install inside OneDrive.
- `config/policy.json` is a list of decisions: `{"id", "date", "words" (chalach verbatim), "rule", "enforced_by"}`.

## 12. Andon: stop new runs in a project

```
ck-run andon raise --project P --reason "<words>"
ck-run andon clear --project P [--note TEXT]
ck-run andon list
```

- While an andon is raised, every new run and review of that project is refused (exit 2):
  `ANDON raised for <name>: <reason> (raised <ts>). Clear it: ck-run andon clear --project <name> --note "<words>"`.
- `<name>` = the ask's project if it has one, else the workspace key (`devfab`, `nv`, `washu`).
- State: `<runs_dir>/.andon/<name>.json`. Ledger event `andon` (status `raised` or `cleared`).
- Use it for exit 4 or 5: raise, tell chalach, and clear only with chalach's words.

## 13. Race and panel

```
ck-run race --ask A --prompt-file F --title T --workspace W [--models astra,opus,grok] [--mode read|auto] [--timeout S]
ck-run race show --ask A
ck-run panel RUN --by codex,claude,cursor --trigger T [--ask A] [--focus TEXT]
```

- **race**: the same task to 2 or 3 models at once. For each alias, ck-run copies F to
  `~/PhD_local/agent_runs/<A>-race-<alias>_prompt.md` and launches slug `<A>-race-<alias>` with
  `run --model <alias> --ask A ...`. Ledger `race`. It prints the slugs. Default models: `race_default`
  (astra, opus, grok). `--mode` is `read` by default (a question); `auto` lets each racer write.
- **race show**: the race runs' summaries side by side (plain text). Grok Bot then writes ONE answer and says where
  the models disagree.
- **panel**: one launched review per agent in `--by` (slug `<A>-panel-<agent>`), all of the same run, with the same
  reason. Ledger `panel`. Each reviewer must be another agent than the reviewed run's. Without `--focus`, each
  reviewer gets its own lens; without `--ask`, the reviewed run's ask.
- Budget: race and panel runs start at the same time, so they need room in the ask's budget. A race sets its own
  runs and parallel (4.2). Each panel review counts as a review and as a live run, so use a panel in an L ask: its
  budget allows 2 reviews (for 3 reviewers, set `reviews=3` in the `--plan` budget line). Reviewers over the budget
  stop with exit 7 (see their `.out`). The same holds for a split: parts that run at the same time need parallel ≥ 2
  (L, or `--parallel N --because` at open).

## 14. Loop: improve one number step by step

```
ck-run loop --ask A (--agent X | --model ALIAS) --prompt-file F --workspace W --metric "<shell cmd>"
            --target "<op><number>" --max N [--cwd DIR] [--title T]
            [--timeout S] [--tier fast|strong|top] [--write-scope FOLDER ...]
```

Start it detached: `ck-run launch <slug> loop ...`. `--max` is 1 to 100. `--cwd` defaults to the workspace root.
`--timeout`, `--tier` and `--write-scope` are passed to each round's run.

- Each round runs `ck-run run ... --ask A` (with `--parent <previous run>` after the first round) and waits for it.
- Then it runs the metric command (`/bin/bash -c` in `--cwd` with a clean environment: no keys or tokens, your PATH;
  timeout 600 s) and takes the LAST number in its output. If a round changes the metric script itself (the program, or
  the script given to python3/bash/...), the loop stops with exit 4 instead of running agent-edited code.
- It writes a row to `~/PhD_local/agent_runs/<A>/loop_decisions.tsv` (ts, i, run_id, metric, kept) and a `loop_iter`
  ledger event (`i=<n> metric=<value> kept=<yes/no>`).
- The next round's prompt = F plus a short "Loop so far" block (the metric history).
- It stops at the target, at N rounds, after 2 rounds without improvement, or when a run exits 2, 4, 5 or 7.
- `--target`: an operator and a number, for example `">=<number>"`. Operators: `>=`, `<=`, `>`, `<`.
- `kept=no` is only a record: ck-run does not undo files. Write in F what the agent should do with a change that did
  not help.
- The metric must be a cheap local check (closed form, quasi-static solver, a test). Never a cloud simulation.
- Budget: every round is a run of the ask. Rounds after the first also count as fixes because they use `--parent`.
  For N rounds, open an L ask with `--pattern loop` and a plan line such as
  `budget: runs=<N> fixes=<N minus 1> wall_min=<minutes>` (replace the placeholders with numbers), or exit 7 stops it.

## 15. result.json v4 (what agents return)

The agent's JSON result has these new fields. All are required; "none" is an empty list or an empty string.

| Field | Content |
|---|---|
| `plain_summary` | 1 to 3 lines in plain words. No paths, no run ids. (The finish card's "Changed" line.) |
| `verification` | `hardware`, `local_sim`, `fake_or_tests`, `desk_check` or `not_checked`: the lowest TRUE level. |
| `decisions` | List of `{what, why, source, ref}`. `source` = `paper`, `datasheet`, `measured`, `simulated`, `chalach` or `guess`. |
| `later` | Ideas NOT done. Nobody does them until chalach says so. |
| `you_should_know` | 0 to 2 lines that teach chalach the key fact. |
| `your_move` | What chalach should do next, or `""` / `"nothing"`. |
| `numbers[].what_else`, `numbers[].limit` | For each number: what else it could be, and what limits it (may be `""`). |

The prompt tells every agent: do only the steps in the task; put extra ideas in `later`; fill the new fields
honestly; give the lowest true verification level; a source tag on every choice; no invented numbers.
`summary.md` stays as before. The review schema does not change.

## 16. Post-run review: off

- New config key `post_review.enabled`, default **false**. Then cursor and agy auto runs get no Claude review after
  the run. The result note says:
  `post-run review disabled by policy`.
- The rule check still runs on every run: raw folders, writes outside the task folder, credentials, cloud sims.
- To turn the review on again, set `post_review.enabled` to true in `config/workspaces.json`.
